# Подготовка выпуска

**Русский** | [English](RELEASING.en.md)

Стабильный тег публикуется только после проверки сборок и артефактов.

## Предварительная сборка без публикации

1. Сначала слейте запланированные PR и дождитесь зелёного CI на `main`.
2. В GitHub откройте **Actions → Release → Run workflow**. Выберите ветку
   `main` и укажите точный новый тег `vX.Y.Z`. Тег `v0.1.0` уже опубликован;
   форма workflow по умолчанию подставляет его, поэтому замените это значение.
3. Убедитесь, что workflow собрал CLI Linux/Windows и SDK Linux, Windows,
   macOS, Android и iOS. Ручной запуск не создаёт релиз и не записывает в git.
4. Скачайте артефакты каждого job. Сверьте SHA-256, распакуйте SDK и проверьте
   заголовок, библиотеки, примеры, документацию и лицензии; проверьте SBOM.
   SDK jobs также компилируют и запускают минимальных C-потребителей там,
   где это поддерживает runner, и проверяют мобильные заголовки/библиотеки.
5. Запишите SHA исходного `main`-коммита этого запуска. Не меняйте `main` до
   публикации. Если он изменился, выполните предварительную сборку заново.

## Публикация

Создайте новый, ранее не использованный тег `vX.Y.Z` и отправьте его на точно
тот commit SHA, который проверен предварительной сборкой. Никогда не
перемещайте и не переиспользуйте опубликованные теги. Tag workflow повторно
собирает файлы, checksums, лицензии и CycloneDX SBOM и прикладывает их к
релизу. Отдельно GitHub публикует build provenance attestation для файлов;
это проверяемая запись в GitHub, а не отдельный скачиваемый asset. Сравните
имена опубликованных файлов и SHA-256 с предварительными артефактами.
Скачанный файл можно проверить командой
`gh attestation verify <файл> --repo ERGFT/vpn-core`; подробности — в
[официальном руководстве GitHub CLI](https://cli.github.com/manual/gh_attestation_verify).

Android/iOS артефакты проверяются кросс-компиляцией и линковкой; это не
подтверждает запуск на физических устройствах. Внешнего криптографического
аудита REALITY пока не было; см. [внутренний отчёт](reviews/2026-11-04-reality-internal-review.md).
