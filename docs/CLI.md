# Командная строка и автозапуск

**Русский** | [English](CLI.en.md)

Все ключи `reality-client` для запуска с одной ссылкой и установка автозапуска. Для нескольких серверов и правил — [файл настроек](CONFIG.md).

## Файл настроек

Обычный запуск с конфигурацией и проверка её загрузки:

```sh
reality-client --config config.json
reality-client --config config.json --check
```

`--check` загружает настройки и строит приложение, затем выходит с результатом; он не запускает прокси и не проверяет доступность сервера или реальный VPN-трафик. Поля и ограничения конфигурации описаны в [руководстве по CONFIG](CONFIG.md).

## Запуск

```sh
# ссылка — в первой строке файла, файл — только для себя
printf '%s\n' 'vless://UUID@host:443?encryption=none&security=reality&sni=site.example&pbk=KEY&sid=SHORTID&type=tcp&flow=xtls-rprx-vision' > server.txt
chmod 600 server.txt
reality-client --server-file server.txt --listen 127.0.0.1:1080
```

- `--server-file` — файл со ссылкой (первая непустая строка); то же —
  переменная окружения `REALITY_SERVER`. Есть и `--server 'vless://…'`
  (ссылка целиком, в кавычках: в ней есть `&`), но ⚠️ аргументы командной
  строки видны всем пользователям машины (список процессов), а в ссылке —
  ваш UUID; клиент тогда печатает предупреждение.
- `--listen` — адрес локального прокси, по умолчанию `127.0.0.1:1080`.
  На этом порту и SOCKS5, и HTTP-прокси (вид определяется по первому байту).
- `--auth логин:пароль` — требовать логин и пароль на SOCKS5 и HTTP proxy
  (Basic). Один набор credentials используется обоими протоколами на этом
  `mixed`-входе. Протоколы прокси сами по себе не шифруют учётные данные;
  HTTP Basic также не шифрует их без TLS. Слушать не
  только на `127.0.0.1` без пароля клиент отказывается. То же без
  командной строки — `--auth-file файл` или `REALITY_SOCKS_AUTH`. Если прокси
  слушает в сети, пароль должен быть не короче 12 байт в UTF-8.
- `--allow-ip адреса` — кому из сети можно пользоваться прокси (адреса
  или подсети через запятую: `192.168.1.23,192.168.1.40`). Если список
  задан, loopback-адреса разрешены автоматически, а LAN-адрес клиента нужно
  добавить явно. Пустой список не ограничивает адреса клиентов.
  После 5 неверных паролей подряд адрес блокируется на
  минуту (дальше — вдвое дольше, до часа).
- `--allow-insecure` — разрешить ссылку с `security=none`. Без этого ключа
  клиент такую ссылку не запустит: UUID и весь трафик пошли бы открытым
  текстом.
- `--max-conns N` — сколько соединений обслуживать одновременно
  (по умолчанию 512); лишние сразу закрываются.
- `--ca файл.pem` — свои корневые сертификаты для `security=tls`
  (сервер с самоподписанным сертификатом).
- `--sniff` — если приложение присылает IP, а не имя, узнать имя по
  первым байтам (TLS SNI, HTTP Host) и отдать серверу имя.
- `--system-proxy` (Windows) — на время работы включить системный
  прокси: браузеры и большинство программ пойдут через клиент без
  настройки. При выходе (Ctrl+C, закрытие окна) прежние настройки
  возвращаются; если клиент был убит жёстко — `--system-proxy-off`.
- `--no-xudp` — UDP без XUDP (отдельный поток на каждое назначение) —
  для серверов, не знающих XUDP.
- Журнал — в stderr, уровень `info` по умолчанию; `--log-file файл` —
  в файл: права только владельцу (0600; в журнале имена серверов и
  адреса клиентов прокси), дорос до 10 МБ — во время работы уходит в
  `.old` (прежний `.old` заменяется). Адреса посещаемых сайтов на уровне
  `info` не пишутся — только при `RUST_LOG=debug`.

## Автозапуск

**Windows, служба** (запуск при старте системы, до входа — нужна для
TUN; от имени администратора):

```bat
reality-client --service-install --config C:\путь\config.json
reality-client --service-uninstall
```

Файл настроек, файлы, на которые он ссылается (они должны лежать в той же
папке), и сам `reality-client.exe` (с `wintun.dll`) копируются в
`%ProgramData%\RealityClient` — туда писать могут только SYSTEM и
администраторы: служба работает от SYSTEM, и exe или настройки, доступные
на запись обычному пользователю, позволили бы любой его программе
получить права системы. Папку, созданную заранее не администратором,
установка не принимает (удалите её и повторите). Журнал —
там же, `reality-client.log`. Изменили настройки — снова
`--service-install` (служба обновится и перезапустится). После сбоя служба
перезапускается сама (через 5 с, 30 с, 2 мин).

**Windows, при входе пользователя** (для `--system-proxy`: системный
прокси — настройка пользователя):

```bat
reality-client --autostart-install --config C:\путь\config.json --system-proxy
reality-client --autostart-uninstall
```

Запускается без окна, журнал — `reality-client.log` рядом с настройками.

**Linux** — systemd: [`examples/reality-client.service`](../examples/reality-client.service)
(настройки в `/etc/reality-client`, из прав root — только `CAP_NET_ADMIN`
для TUN, `systemctl reload` перечитывает настройки без разрыва соединений).

## Восстановление после аварийного завершения

`--tun-cleanup` снимает оставшиеся правила маршрутизации и блокировку
`strict_route` на Linux либо WFP kill switch на Windows, затем завершает
работу. На Linux удаляются только помеченные правила и маршруты. На обеих
платформах очистка не выполняется, пока запущенный клиент удерживает
блокировку `auto_route`. Используйте команду, если аварийное завершение
оставило TUN-защиту включённой. Команда изменяет
системное сетевое состояние и может потребовать повышенных прав. На других
платформах этот режим не поддерживается.

Проверка, что всё работает:

```sh
curl --socks5-hostname 127.0.0.1:1080 https://example.com
```

В браузере — указать SOCKS5-прокси `127.0.0.1:1080` (в Firefox —
«Параметры соединения», вместе с «DNS через SOCKS v5»).
